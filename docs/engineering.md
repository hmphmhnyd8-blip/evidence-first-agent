# 工程设计与已知限制

## 为什么数值交给工具

模型不生成 SQL，也不指定数据库路径。工具输入是船号，SQLite 使用绑定参数和只读 URI。`COUNT(*)` 与 `COUNT(sog)` 分别表示总记录与有效数值记录，`AVG` 忽略 NULL 而包含 0。无记录与全部缺失具有不同状态，让上层能解释事实边界。

## 为什么采用子图

外层负责工具选择和会话，资料子图负责检索、检查、必要时改写一次。以 `chunk_id` 合并去重保留首次证据；改写附带原问题，降低实体或时间范围丢失的风险。每次工具调用初始化子图状态，不让上一个问题的“证据充分”状态泄漏。

## 能保证什么，不能保证什么

程序可以验证引用编号来自候选集，却不能因此保证原文支持结论。结构化证据检查仍依赖模型，提示词也不能证明防注入有效。当前应由人核对关键结论，不宜作为生产决策依据。

外层在第 6 次模型请求后仍执行该次提出的工具，再停止继续请求。每次资料工具内部最多 3 次模型请求，但外层可在一次回复中提出多个工具，尚未建立全局成本上限。内部计数是正常完成的调用数；失败请求会抛出并终止当前子图，未实现跨重试账本。

多轮对象解析依赖模型与历史消息，非确定性实体状态机。历史消息无限累积，尚无压缩与持久化。日志记录工具参数与结果，使用真实数据时需要额外设计脱敏、保留期与访问控制；日志默认不提交 Git。

## 为什么没有默认使用 RRF

小规模开发实验中融合与向量的总体 Hit@5 相同，且部分题目退步。不能仅因融合更复杂就认定更好。保留实验实现供比较，主检索工具保持向量方案；进一步选择应在冻结保留集上评估。

## 发布版做了什么

把学习脚本按职责重新命名；抽离工具运行时的重复日志函数与无关入口；为轻量测试延迟导入向量依赖；环境变量优先于本地 .env；添加可重建的演示数据、依赖清单、回归测试和 CI。没有将这些整理工作写成生产规模、性能提升或上线业务收益。
